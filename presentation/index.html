CONCEPTUAL FOUNDATIONS • SLIDE 02

What Is an AI Agent?

Beyond static text completion: The convergence of perception, internal state, reasoning, and environmental feedback

THE AGENCY THEOREM Perception + Internal State + Reasoning + Action + Environmental Feedback = Agency

📖 The Recipe Reader (Raw LLM)

Follows a printed list of instructions linearly. If an ingredient is missing, the flame burns too high, or an oven malfunctions, it blindly proceeds or crashes because it lacks sensory perception and environmental feedback. It emits tokens without knowing reality.

🍳 The Executive Chef (Autonomous Agent)

Given an open-ended goal ("Prepare dinner for four"), it inspects the pantry (Perception), plans courses (Reasoning), cooks (Action), tastes the sauce and adjusts seasoning (Feedback), and substitutes ingredients dynamically until a delicious meal is achieved.

STAGE 01

Perception Phase

Ingests user prompts, environment state, file trees, database schemas, and structured return data from previous tool executions.

STAGE 02

Reasoning & Action

Synthesizes structured thoughts, decomposes tasks, validates arguments via JSON schemas, and invokes tools to affect reality.

STAGE 03

Reflection & Adaptation

Evaluates real-world observations against criteria, diagnoses error messages, and dynamically adapts plans until completion.

REACTIVE INTERACTION

Traditional Chatbot

Passive conversational token generator
1. Primary Objective

Generate fluent, contextually plausible textual responses to human prompts.

2. Execution Model

Single-turn request/response pipeline. Execution stops immediately when the token stream finishes.

3. Environmental Agency

Zero Agency. Confined strictly to emitting tokens within the active chat window.

4. Error Recovery

Cannot detect errors in its own output; relies entirely on human follow-up prompts to re-steer.

5. Memory Architecture

Transient conversational buffer strictly bounded by context window limits. Forgets across sessions.

AUTONOMOUS EXECUTION

Autonomous AI Agent

Proactive environmental operator & reasoning engine
1. Primary Objective

Achieve multi-step real-world objectives through autonomous planning and execution.

2. Execution Model

Multi-turn iterative cycle (Thought → Action → Observation) driven by an agent runtime loop.

3. Environmental Agency

High Agency. Executes code, queries SQL databases, invokes REST APIs, and modifies files.

4. Error Recovery

Autonomous self-correction: reads error logs from tool observations and replans dynamically.

5. Memory Architecture

Hierarchical: short-term working context plus persistent long-term storage (Vector DBs, KV stores).

Key Takeaway: Chatbots communicate with humans; AI agents collaborate with environments to accomplish work. [S03] • [S04] • CLM-002, CLM-003
SYSTEM ARCHITECTURE • SLIDE 04

Core Agent Architecture

The six structural pillars that transform a foundation model into an autonomous agent runtime

INSTRUCTIONS & REASONING

System prompts constrain role, safety guidelines, and task criteria. The foundation model performs contextual inference without modifying its weights.

TOOLS & ENVIRONMENT

Registered executable interfaces allow the model to interact with reality. The model never modifies reality directly; tools act as its effector organs.

MEMORY & RUNTIME LOOP

Maintains short-term state and long-term knowledge across turns while the runtime schedules execution turns until an objective or stop condition is met.

COGNITIVE STRATEGIES • SLIDE 05

Planning and Reasoning

How intelligent agents break down intractable objectives and recover from intermediate failures

01

Task Decomposition

Raw language models suffer from myopic token generation: predicting next tokens without global foresight leads to compounding drift.

Decomposition forces the agent to break an ambiguous objective (e.g. "Deploy web app") into an ordered sequence of discrete sub-problems: provision DB, configure DNS, execute unit tests, and deploy.

02

Plan-and-Solve

Separates the deliberation phase from execution. The agent first synthesizes a formal execution graph or step list before executing any external tool actions.

Benefit: Dramatically reduces token waste and wandering by establishing an explicit roadmap before invoking external APIs.

03

Self-Reflection

When an intermediate tool returns an unexpected error (e.g. 404 Not Found or SyntaxError), the agent does not crash.

Reflection Loop: The agent inspects the diagnostic trace, formulates a hypothesis of failure, alters arguments, and replans dynamically.

ARCHITECTURAL TRADEOFF: LATENCY & COST VS. RELIABILITY

Extensive multi-step planning and reflection improve task completion rates on complex benchmarks, but each planning turn consumes token quota and adds 1–3 seconds of latency. Practical systems balance deterministic workflows for predictable tasks with agentic loops for exploratory tasks.

STATE MANAGEMENT • SLIDE 06

Memory and Context

Bridging transient context windows and persistent long-term knowledge across sessions

Tier 1: Short-Term Working Memory

Active Context Window Buffer

Active Working State

System persona, user prompt, and immediate conversational turn history.

Tool Observations

Ingests raw outputs from executed APIs, SQL queries, and bash scripts.

Context Compaction

Summarization agents compress older turns to prevent context window overflow.

Tier 2: Long-Term Persistent Memory

Durable Multi-Session Storage

Vector Databases

Stores semantic embeddings of past experiences, docs, and codebases for RAG retrieval.

Key-Value Stores

Stores persistent facts: user preferences, API configurations, and project identities.

Relational DBs

Tracks transactional state machines, checkpoints, and multi-step workflow graphs.

MEMORY CONSOLIDATION PIPELINE

When an agent finishes a task, modern frameworks run an offline memory consolidation step: extracting key learnings, user preferences, and failure patterns from working memory, embedding them, and indexing them in the vector store so future agent runs benefit from past experience.

ENVIRONMENTAL INTERFACES • SLIDE 07

Tools and Function Calling

Actuators that transform language models into real-world software operators

01

Tool Registration

Developer exposes tool signatures to the model using JSON Schema (declaring function name, docstring description, parameter types, and required fields).

02

Tool Call Generation

The LLM analyzes the user prompt, determines that an external calculation or API lookup is needed, and emits a structured tool invocation object: {"name": "fetch_weather", "arguments": {"city": "Tokyo"}}

03

Client Execution

The agent runtime intercepts the tool call, validates the parameters, and executes the actual Python function, SQL query, or REST API request.

04

Observation Injection

The runtime formats the tool output and injects it back into the model's context as a new message with role: "tool".

CANONICAL REASONING PARADIGM • SLIDE 08

The ReAct Pattern: Reasoning and Acting

Synergizing reasoning traces and task-specific actions to eliminate hallucinations (Yao et al., 2022)

THOUGHT (Internal Reasoning) Model verbalizes logic, tracks goals & plans next action.
ACTION (External Actuator) Emits explicit tool call with verified schema arguments.
OBSERVATION (Ground Truth) Environment returns actual empirical result back into context.
Goal: What is the population of Paris divided by 2?
Thought 1: I need to find the current population of Paris.
Action 1: search_kb["population of Paris"]
Observation 1: The population of Paris is 2,161,000.
Thought 2: Now I must divide 2,161,000 by 2.
Action 2: calculate["2161000 / 2"]
Observation 2: 1080500.0
Thought 3: I have verified the result via calculation.
Final Action: finish["The population of Paris divided by 2 is 1,080,500."]

ORCHESTRATION TOPOLOGIES • SLIDE 09

Agent Loops vs. Graph Orchestration

Deterministic workflows, autonomous loops, and the unified state graph architecture

Static DAG Workflows

Deterministic code pipelines: Execution flow is hardcoded in advance (Prompt Chaining, Parallel Routing, Evaluator-Optimizer).

Anthropic View [S03]: Prefers deterministic workflows wherever possible. LLMs generate content, but human code directs the flow for predictable cost and safety.

Autonomous Cyclic Loops

Dynamic while-loops: The foundation model controls its own path: choosing tools, iterating, and deciding when to terminate.

Characteristics: Essential for open-ended tasks (e.g. debugging code, deep web research), but harder to predict and bound against runaway loops.

Stateful Graphs (LangGraph)

Unified Graph Abstraction: Reconciles deterministic workflows and autonomous loops as Nodes (computations) and Edges (transitions).

LangChain View [S06]: A state graph provides cyclic transitions with deterministic state channels, persistence, and human checkpoints.

ARCHITECTURAL RECONCILIATION (DOCUMENTED DISAGREEMENT)

Anthropic [S03] draws a sharp conceptual dichotomy between Workflows (deterministic code routing) and Agents (model-directed loops). LangGraph [S06] resolves this by demonstrating that both are instances of stateful computational graphs differing only in whether edge branching is static or conditional.

COLLABORATIVE ARCHITECTURES • SLIDE 10

Single-Agent vs. Multi-Agent Systems

Coordination topologies: Sequential pipelines, hierarchical supervisors, and swarm hand-offs

👤 Single-Agent Systems

One centralized foundation model with all instructions and tools loaded into a single context window. Straightforward to debug with low latency and zero inter-agent communication overhead, but vulnerable to context saturation, prompt interference, and performance degradation when juggling disparate domain instructions.

👥 Multi-Agent Systems (MAS)

A team of specialized agents, each with dedicated system prompts, constrained toolsets, and isolated context windows. Enables clean role specialization (Researcher + Coder + Reviewer) and parallel execution, but incurs higher token consumption, potential communication loops, and coordination overhead.

1. Sequential Pipeline

Agent A performs research → passes brief to Agent B (Writer) → passes draft to Agent C (Editor). Linear handoff.

2. Hierarchical Supervisor

A central Router / Manager agent receives the primary goal, decomposes tasks, dispatches worker sub-agents, and synthesizes output.

3. Peer Handoff / Swarm

Agents transfer conversation control dynamically to specialized peers (e.g. Triage → Billing → Tech Support) via direct delegation.

def run_react_agent(query, max_steps=3):
    state = {"query": query, "history": []}
    for step in range(max_steps):
        thought = plan_thought(state)
        action, arg = select_tool(thought)
        if action == "finish":
            return arg
        observation = execute_tool(action, arg)
        state["history"].append((thought, action, observation))
    return "Reached maximum steps."

SAFETY, EVALUATION & SUMMARY • SLIDE 12

Evaluation, Safety & Future Horizons

Industry benchmarks, security guardrails, and core curriculum takeaways

📊 Standardized Agent Benchmarks

  • SWE-bench: Evaluates agents on resolving real-world GitHub issues (cloning repos, writing code, executing unit tests). Measures real end-to-end coding ability.
  • GAIA (General AI Assistants): Evaluates multimodal assistants on real-world tasks requiring web browsing, file parsing, multi-modal reasoning, and complex tool usage.

🛡️ Critical Safety Guardrails

  • Prompt Injection (Direct & Indirect): Malicious text embedded in crawled webpages or emails instructing the agent to exfiltrate private user tokens.
  • Tool Sandboxing: Agents executing shell scripts or SQL must run in isolated containerized environments with least-privilege credentials.
  • Human-in-the-Loop (HITL): Requiring explicit human approval before financial transactions, database mutations, or public messaging.

1. AGENTS ACT

LLMs write text; agents perceive environments, execute tools, and recover from failures autonomously.

2. REACT SYNERGIZES

Interleaving thoughts and empirical tool observations eliminates hallucination and grounds execution.

3. START SIMPLE

Prefer deterministic workflows first; scale to cyclic graphs or multi-agent swarms only when complexity demands.
