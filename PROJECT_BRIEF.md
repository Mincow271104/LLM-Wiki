# Project Brief — AI Agents Learning Wiki

## Approved requirements

- **Topic:** AI Agents: Concepts, Architecture and Workflow.
- **Primary audience:** AI beginners.
- **Learning scope:** comprehensive introduction, from definitions and architecture to loops, graph orchestration, implementation, multi-agent systems, evaluation, and safety.
- **Technical approach:** hybrid; explain framework-independent concepts, compare representative frameworks, and include a small Python teaching example.
- **Language:** English only.
- **Evidence policy:** strict source validation, claim-level attribution, explicit uncertainty, and a contradiction register.
- **Planned sources:** eight curated academic, official-documentation, and practical sources; minimum accepted ingestion count is five.
- **Final presentation:** approximately 10–12 interactive HTML slides, written for beginners.
- **Agent environment:** Antigravity.

## Method

Follow the Karpathy-inspired LLM Wiki approach:
1. Discuss and clarify requirements before creating project files.
2. Keep original source material separate from synthesized Wiki knowledge.
3. Maintain an explicit schema/instruction file for future agent sessions.
4. Support ingest, query, and lint operations.
5. Use the Wiki as the evidence base for the teaching presentation.

## Workflow principles

- A Graph controls the major stages and explicit return routes.
- Local Loops handle bounded correction within individual stages.
- A stage may be retried at most three times.
- Stop and report when required evidence is unavailable.
- The independent review stage must inspect the output and its evidence, not merely approve its own generation.
- Preserve real execution logs. Never invent successful tests.

## Required deliverables

1. Wiki topic and introduction.
2. Public Wiki/repository link or project files.
3. Working teaching HTML presentation and accessible link/file.
4. Loop/Graph diagram and explanation.
5. Actual execution and validation evidence.
6. Reflection on the most error-prone stage and changes to earlier checks.

## Deadline-aware implementation order

1. Preserve and finish the Wiki with at least five verified ingested sources.
2. Generate and locally verify the HTML presentation.
3. Complete the Graph and actual execution evidence.
4. Write the reflection and Moodle submission text.
5. Publish the website and repository if time permits.

## Student metadata

Student ID, exact program/class designation, and full submission title must be filled in by the project owner. Do not guess these fields.
